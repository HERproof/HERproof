# How HerProof works

A map of the repo: what every folder and file does, and how data moves between them.
To just see the product, follow [See it](../README.md#see-it) in the README.

## The flow

```
 ┌──────────── 1. CAPTURE ────────────┐   ┌──── 2. ORGANIZE ────┐   ┌──── 3. EXPORT ────┐
 iPhone ─USB─► capture/herproof/extract.py ─┐
                                            ├─► entries.json ─► organize.py ─► timeline.json ─► export_packet.py ─► packet.html
 folder of screenshots / WhatsApp .txt ─► ingest.py ─┘                                                                  │
                                                                                                                      │
 ┌──────────── 4. WEB ─────────────────────────────────────────────────────────────────────────────────────────────┐ │
 web/pattern-map/app.html  reads  capture/evidence/<run>/, /timeline.json, /packet.html  ◄───────────────────────────┘ │
 capture/server.py serves the site and runs steps 1 to 3 when the app asks for a capture                              │
 └─────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

| Step | Input | Output | Uses AI? |
|---|---|---|---|
| Capture from an iPhone | the phone, over USB | screenshots + `entries.json` | Text comes from iOS's accessibility tree (no OCR). Claude or Gemini flags abusive messages, with a keyword fallback |
| Ingest a folder | screenshots, photos, WhatsApp `.txt` | `entries.json` | Gemini reads text off screenshots. WhatsApp exports are parsed locally |
| Organize | `entries.json` | `timeline.json` | Only for the neutral incident summaries. The CDC pattern tags are fixed rules |
| Export | `entries.json`, `timeline.json`, the original files | `packet.html` | No |

Every file gets a SHA-256 fingerprint when it comes in. `export_packet.py` checks each one
again when it builds the packet and marks any file that changed.

## Repo root

The pipeline lives at the root because `capture/server.py` runs `organize.py` and
`export_packet.py` from here, and the web app loads `/timeline.json` and `/packet.html` from
here. Don't move these files.

| File | What it does |
|---|---|
| `index.html` | Forwards the site root to the app (`web/pattern-map/app.html`) |
| `ingest.py` | Step 1 for a folder: fingerprints each file, reads photo dates, sends screenshots to Gemini to read the messages, parses WhatsApp exports. Writes `entries.json` |
| `whatsapp.py` | WhatsApp `.txt` parser for iOS and Android exports. Skips system notices, marks attachments. Your display name maps to "self" (`--self "Name"` or `HERPROOF_SELF_NAME`) |
| `organize.py` | Step 2: merges messages, removes the overlap between consecutive screenshots, dates undated messages by the screenshot's capture time ("on or before"), sorts, tags patterns, groups incidents on gaps over 6 hours, asks Gemini for a neutral summary of each, and builds the review flags. Writes `timeline.json` |
| `matchers.py` | The pattern rules. Regex only, no model. Each category maps to a CDC NISVS survey item and carries its national prevalence figure. Only the other person's messages are tagged |
| `export_packet.py` | Step 3: builds `packet.html` in the attorney packet design: cover, DV-100 items 1 to 9, CLETS-001, flagged forms, the item 5c attachment, the exhibit list with re-checked fingerprints, the embedded original images, flags, and the method page. Names, addresses and orders stay blank on purpose |
| `llm.py` | One place that calls Gemini (`google-genai`). Model set by `HERPROOF_MODEL` |
| `timeutil.py` | Puts every timestamp in one form (local wall-clock time) so different sources sort together |
| `requirements.txt` | Python packages for the pipeline |
| `entries.json`, `timeline.json`, `packet.html` | The pipeline's current output from the demo data. Regenerated by every run |
| `.env` | Your `GEMINI_API_KEY` (not committed) |

## `capture/`: reading the iPhone

A Mac drives an unlocked iPhone over USB, opens Messages, walks one conversation from
newest to oldest, and screenshots every screen: once plainly, and once with each message's
time revealed. It is read-only: it never types, sends, reacts or deletes. Setup and the
full guide are in [`capture/README.md`](../capture/README.md) and
[`capture/SETUP.md`](../capture/SETUP.md).

| File | What it does |
|---|---|
| `server.py` | The demo server. Serves the whole repo on port 8000 and adds `/api/phone` (is an iPhone connected), `/api/runs` (saved captures), `/api/capture` (start one, then run organize and export) and `/api/status`. Python standard library only |
| `herproof/extract.py` | Walks one conversation, takes the screenshots, flags messages, writes the capture index |
| `herproof/messages.py` | Turns the Messages app's accessibility tree into message records |
| `herproof/phone.py` | Small client for the iphone-use daemon that controls the phone |
| `herproof/classify.py` | Flags abusive messages with Claude or Gemini, or keywords when there's no key |
| `herproof/entries.py` | Converts a capture into the `entries.json` format, so the root pipeline runs on it unchanged. Also writes `messages.txt` and `capture-tags.json` for the Pattern Map |
| `herproof/llm.py` | Claude and Gemini behind one call, for capture |
| `herproof/agent.py`, `herproof/tools.py` | Optional mode where a model drives the phone itself through a fixed set of tools |
| `scripts/` | Shell helpers: record the phone screen (`record.sh`), take one screenshot (`snap.sh`), reveal message times and grab the right frame (`times_snap.sh`, `pick_frame.py`) |
| `setup/` | One-time Mac setup (`install.sh`) and a fix for a known setup failure (`patch-setup-wda.sh`) |
| `tasks/team2-today.md` | A written task for a supervised capture run |
| `.env.example`, `requirements.txt` | Capture's own settings and packages |
| `evidence/<run>/` | Where captures are saved: screenshots, `entries.json`, `capture-tags.json`, optional `recording.mp4`. Not committed, because it holds phone data |

## `web/`: the app survivors use

A static site: plain HTML and JavaScript, no build step. Serve it from the repo root.

**The app**

| Page | What it is |
|---|---|
| `pattern-map/app.html` | **The main app.** Cora guides the survivor through: hello, account (a PIN that is the encryption key), 1 connect the phone, 2 what came across, 3 working through it, 4 the map, 5 the DVRO packet, 6 send it on. Disguise mode (D) turns the screen into a recipes app; Quick Exit leaves at once |
| `index.html` | The same flow with the animated landing page on top. Used for the live presentation ([`SCRIPT.md`](../web/SCRIPT.md)) |
| `landing-anim.css`, `landing-anim.js` | The landing animations for `index.html` |
| `pattern-map/brand.js`, `pattern-map/axolotl.png` | Shared brand bar and Cora the axolotl |
| `photos/` | Demo photo-library images the app surfaces during the photo scan |

**Pages the app and the forms flow link to**

| Page | What it is |
|---|---|
| `pattern-map/pattern.html` | The pattern: month heat grid, full timeline with the gap and the clusters, time of day |
| `pattern-map/vault.html` | The vault export: sources, fingerprints and dated incidents, as JSON or a readable page |
| `pattern-map/exhibits.html` | Photo exhibits with dates, fingerprints and where each attaches |
| `pattern-map/packet.html` | The designed DVRO packet that `export_packet.py` follows |
| `pattern-map/jurisdictions.html` → `dvro-forms.html` → `dvro-fill.html` | Restraining order forms by state, then the California form list with official links, then on to the packet |

**Other pages**

| Page | What it is |
|---|---|
| `pattern-map/index.html` | Pattern Map: loads a capture run by name (`messages.txt` + `capture-tags.json`) and shows the conversation with its flags. Used to check a capture ([`capture/README.md`](../capture/README.md)) |
| `pattern-map/config.example.js` | Template for the optional `config.js` (Gemini key for Cora's voice and the Pattern Map text pass, Supabase). `config.js` is not committed |
| `landing/index.html` | Earlier standalone landing page |
| `pattern-map/flow.html`, `pattern-map/report.html` | Earlier flow: make the vault, dashboard, send to an attorney, and the attorney report it produced |
| `pattern-map/dv100-filled.html` | DV-100 and CLETS-001 filled with sample California data |
| `pattern-map/main logo page.html` | The logo and hello screen |
| `pattern-map/sample-conversation.txt` | A demo chat to import by hand: 18 months, escalating, with harmless look-alikes and a silent stretch |
| `supabase/schema.sql` | Optional database for the Pattern Map. Stores tags and counts, never message text |

**Docs**

| File | What it is |
|---|---|
| `ARCHITECTURE.md` | The design reasoning: nothing leaves the device, and the taxonomy is the CDC's |
| `SCRIPT.md` | The 3 minute live demo script |
| `golden-docs/` | The target documents: one each for a lawyer, the police and the survivor, plus `04-dvro.md`, the attorney packet spec |

## Settings

| Where | What |
|---|---|
| `.env` (root) | `GEMINI_API_KEY`, optional `HERPROOF_MODEL` and `HERPROOF_SELF_NAME` |
| `capture/.env` | Phone connection settings and the classifier's API key (see `capture/.env.example`; `setup/install.sh` writes it) |
| `web/pattern-map/config.js` | Browser keys (`window.HERPROOF_CONFIG`); copy `config.example.js` |

None of these are committed. Before real evidence goes through the pipeline, uncomment
the data lines in `.gitignore` so it can never be pushed.
